# LinkTree — Telegram-бот с курируемой базой dev-ресурсов и семантическим поиском

Бот хранит **лично отобранную** базу полезных GitHub-репозиториев, инструментов и сервисов
(187 записей на старте, 14 категорий, описания на русском и английском). Пользователь пишет
запрос обычным языком — бот находит релевантное **по смыслу**, а не по вхождению слов.

> «нужна библиотека для работы с PDF в Python» → pdfplumber, pypdf
> «запустить нейросеть локально» → Ollama, llama.cpp, vLLM
> «красивый терминал» → Starship, Alacritty, bat, eza

## Возможности

**Пользователям**
- 🧩 **Разбор задачи** (`/plan`) — опиши проект одним сообщением, ответь на 5 вопросов
  шкалой 1–5 — и бот детерминированно (ядро МАРСИ, без нейросетей) разложит задачу
  на атомарные шаги, подберёт к каждому инструмент из базы и выстроит порядок
  с первопричиной; шаги закрываются кнопками, план пересчитывается;
- 🔍 семантический поиск на русском и английском (морфология, синонимы, опечатки);
- 🗂 обзор базы по категориям с пагинацией;
- 🎲 случайный ресурс («открой для себя новое»);
- ⭐ личное избранное;
- ↔️ «похожие ресурсы» от любого результата;
- 👍/👎 голосование, влияющее на ранжирование (relevance feedback);
- 💡 предложения ресурсов с модерацией админом прямо в чате;
- 📮 «ресурс недели» — еженедельный дайджест по понедельникам (opt-in, `/digest`);
- 🌺 интерфейс RU/EN (`/lang`).

**Админам** (`ADMIN_IDS` в конфиге)
- панель `/admin`: пользователи, ресурсы, запросы за 24 ч, топ запросов;
- `/add <json>` — добавить ресурс; `/export` / `/import` — выгрузка/загрузка базы JSON;
- `/pending` + кнопки ✅/🗑 — модерация предложений (автор получает уведомление);
- `/broadcast <текст>` — рассылка с подтверждением; `/ban`, `/unban`; `/reindex`.

**Инженерное**
- антифлуд (окно 6 событий / 10 с), бан-лист, обработка ошибок без падения;
- SQLite (WAL), логи запросов для статистики; i18n с тестом чётности ключей;
- поиск работает полностью офлайн — без внешних API и расходов.

## Как устроен поиск (гибрид, без обязательных зависимостей)

1. **Векторный канал**: мешок слов + символьных n-грамм (fastText-подход: ловит морфологию
   и опечатки) хешируется в 8192-мерный вектор с TF-IDF весами, косинусное сходство.
2. **Лексический канал**: BM25F по полям (title ×3, tags ×2.5, category ×2, ru/en ×1.2).
3. **RU→EN синонимический мост**: ~150 пар («картинки»→image, «нейросети»→neural/ai/ml,
   «парсинг»→scraping…), чтобы русские запросы находили англоязычные репозитории.
4. **Поведенческий сигнал**: лёгкий буст по разнице голосов 👍/👎.

Итог = `0.55·cosine + 0.45·BM25 + boost'ы`; ниже порога 0.10 — «ничего не нашлось».

## 🧩 Разбор задачи: детерминированное ядро МАРСИ

Функция «разбор проекта/задачи» реализует атомарную декомпозицию без единого
вызова LLM (пошаговое анкетирование вместо парсинга текста нейросетью — как
и рекомендует метод):

- **Анкета** кнопками 1–5 даёт строгие нормированные параметры 0..1:
  t — срочность, y — ущерб, g — ясность/достоверность, h — ценность (ROI), R — ресурсы.
- **Декомпозиция:** семантический поиск берёт из базы топ-10 кандидатов («микро-методы»);
  свои шаги пользователя входят в план как обязательные «чёрные ящики» (f = 0.4).
- **Вес ячейки:** `W = (t + m + f + e + y + g + h)/7 · trust + ε`, где m — релевантность
  аспекта запросу, ε — энтропия (растёт при низкой уверенности g).
- **Ресурсозатраты** r — тяжесть категории (awesome 0.3 … ml-ai 0.75) + надбавки
  за тяжёлые теги (kubernetes, engine…). **Приоритет** `B = W·R/(R+r)` — при малых
  ресурсах тяжёлые методы уезжают вниз (ограничитель r_obj).
- **Клей Φ_jk** («лекарственные взаимодействия» инструментов): общий класс
  (formatter/http/orm/telegram…) или ≥2 общих тега в категории → −0.5 (альтернативы,
  выбор одного); одна категория → −0.2; общие теги/известные экосистемы
  (backend+python, web+design…) → +0.15 (синергия).
- **КЛЕЙ плана** = `ΣW − λ·Σr + ΣΦ − N·ε` — жадный отбор максимизирует его
  при бюджете `Σr ≤ R·3`, максимум 5 шагов.
- **Первопричина Z** — шаг с максимальным impact (`W + 0.3·ΣW связанных`):
  обнуление именно него гасит максимум веса системы — с него план начинается.
- **Итерация i → i+1:** «✅ Сделал» обнуляет ячейку и каскадно дисконтирует связанные
  (×0.75), «⏭ Заменить» достаёт следующего кандидата из запаса — план пересчитывается,
  пока всё не закрыто. Каждое число в разборе объяснимо и воспроизводимо.

Опциональные **настоящие эмбеддинги** (меняют канал 1):
- `SEARCH_BACKEND=st` — sentence-transformers (`pip install sentence-transformers`),
  модель из `EMBEDDING_MODEL` (по умолчанию мультиязычная MiniLM);
- `SEARCH_BACKEND=api` — любой OpenAI-совместимый `/embeddings` endpoint
  (`EMBEDDING_API_BASE`, например локальная Ollama: `http://localhost:11434/v1`).

## Быстрый старт

```bash
pip3 install -r requirements.txt        # aiogram + aiosqlite
cp .env.example .env                    # вписать BOT_TOKEN и ADMIN_IDS
python3 bot.py                          # или ./run.sh
```

1. Токен: [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Свой ID: [@userinfobot](https://t.me/userinfobot) → в `ADMIN_IDS`.
3. Первый запуск сам создаёт БД и заливает сид-базу (idempotent, правки не затирает).

## Конфигурация

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BOT_TOKEN` | — | токен от BotFather (обязателен) |
| `ADMIN_IDS` | — | ID админов через запятую |
| `DB_PATH` | `linktree.db` | файл SQLite |
| `SEARCH_BACKEND` | `auto` | `auto`/`local`/`st`/`api` |
| `EMBEDDING_MODEL` | MiniLM | модель для `st`/`api` |
| `EMBEDDING_API_BASE/KEY` | — | endpoint OpenAI-совместимых эмбеддингов |
| `RESULTS_PER_PAGE` | `3` | результатов на страницу |
| `DIGEST_HOUR` | `10` | час рассылки «ресурса недели» |

## Тесты

```bash
pip3 install -r requirements-dev.txt
python3 -m pytest            # 190 тестов
python3 -m pyflakes bot.py config.py db.py i18n.py keyboards.py middlewares.py services.py marsi.py search/*.py handlers/*.py tests/*.py
```

Покрыто: токенизация/морфология, релевантность на реальной базе, related-поиск,
голоса и их влияние на порядок, CRUD/избранное/предложения/статистика, чёткость
i18n, валидация seed, интроспекция регистрации хендлеров, middlewares (троттлинг
с FSM-исключением, баны, ошибки), callback-данные ≤ 64 байт, детерминизм формул
МАРСИ (веса, бюджет, клей, конфликты альтернатив, первопричина, каскад), хранилище
планов и e2e-анкета через Dispatcher с мок-ботом.

## Структура

```
bot.py                 точка входа: сборка, polling, дайджест-цикл
marsi.py               🧩 детерминированное ядро разбора задачи (W, r, B, Φ, клей, Z)
config.py              конфиг из env/.env
db.py                  SQLite: ресурсы, юзеры, избранное, голоса, предложения, планы
i18n.py                RU/EN строки, категории, псевдонимы категорий
keyboards.py           reply-меню, шкала анкеты, инлайн-клавиатуры (вкл. план)
middlewares.py         юзер-контекст (язык/бан), антифлуд (FSM/колбэки exempt), ошибки
services.py            кэш запросов, рендер карточек, пересборка индекса
search/engine.py       гибридный движок (косинус + BM25F + бэкенды эмбеддингов)
search/vectorizer.py   токенизация, RU-нормализация, n-граммы, feature hashing
search/synonyms.py     RU→EN синонимический мост
handlers/user.py       поиск, категории, случайное, избранное, голоса, FSM предложений
handlers/plan.py       🧩 анкета разбора задачи, план, шаги done/skip, пересчёт i→i+1
handlers/admin.py      панель, CRUD, импорт/экспорт, рассылка, модерация, баны
data/seed_resources.json  курируемая база (187 ресурсов)
tests/                 190 тестов
```

## Известные ограничения

- Не тестировался на реальном токене в бою (оплата не нужна, но живой смоук
  `/start → поиск → голос → избранное` стоит прогнать после запуска).
- «Ещё ➡️» держит текст запроса в памяти процесса: после рестарта кнопка попросит
  повторить запрос (сам результат не теряется).
- Групповые чаты не поддержаны осознанно: поиск и меню — только в личке.
